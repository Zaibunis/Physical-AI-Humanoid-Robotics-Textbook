# Data Model: Retrieval-Enabled Agent

This feature is primarily concerned with the flow of data between systems (User -> Agent -> Qdrant -> Agent -> User) rather than a persistent data model with a static schema. The key data entities are ephemeral and represent information in transit.

## Key Entities

### 1. Query
-   **Description**: Represents the input question provided by the end-user.
-   **Fields**:
    -   `text` (string): The verbatim question from the user.
-   **Example**: `{"text": "What is a URDF in ROS 2?"}`

### 2. Retrieved Context
-   **Description**: Represents a single chunk of a document retrieved from the Qdrant vector store that is deemed relevant to the `Query`.
-   **Fields**:
    -   `content` (string): The actual text of the document chunk.
    -   `source` (string, optional): Metadata indicating the origin of the content (e.g., book title, chapter, page number).
    -   `score` (float): The similarity score from Qdrant, indicating its relevance to the query vector.
-   **Example**:
    ```json
    {
      "content": "A URDF (Unified Robot Description Format) is an XML file used in ROS to describe all elements of a robot...",
      "source": "ros-2/urdf.md",
      "score": 0.91
    }
    ```

### 3. Answer
-   **Description**: The final, synthesized response generated by the OpenAI Agent. This answer is constructed based on the information provided in one or more `Retrieved Context` entities.
-   **Fields**:
    -   `text` (string): The complete, human-readable answer.
-   **Example**: `{"text": "In ROS 2, a URDF (Unified Robot Description Format) is an XML file that describes the physical parts of a robot."}`

## State Transitions / Data Flow

The data flows in a clear sequence:

1.  A `Query` is created from user input.
2.  The `Query.text` is used to search Qdrant, which returns a list of `Retrieved Context` objects.
3.  The `content` from the list of `Retrieved Context` objects is passed to the OpenAI Agent.
4.  The Agent processes the context and generates a final `Answer`.
