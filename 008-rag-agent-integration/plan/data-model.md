# Data Model: RAG Agent Frontend Integration

## Frontend Data Structures

### QueryRequest Interface
```typescript
interface QueryRequest {
  query: string;  // The user's question to be processed by the RAG agent
}
```

### MatchedChunk Interface
```typescript
interface MatchedChunk {
  content: string;           // The content of the matched text chunk
  url: string;              // URL of the source document
  position: number;         // Position of the chunk in the source
  similarity_score: number; // Similarity score of the chunk to the query
}
```

### QueryResponse Interface
```typescript
interface QueryResponse {
  answer: string;              // The answer generated by the RAG agent
  sources: string[];           // List of source documents referenced in the response
  matched_chunks: MatchedChunk[]; // Text chunks that contributed to the answer
  error?: string;              // Error message if the query failed
  status: 'success' | 'error' | 'empty'; // Status of the query processing
  query_time_ms?: number;      // Time taken to process the query in milliseconds
  confidence?: string;         // Confidence level of the response
}
```

### UI State Interface
```typescript
interface ChatUIState {
  query: string;                                    // Current query input
  response: QueryResponse | null;                   // Last response from RAG agent
  isLoading: boolean;                              // Loading state indicator
  error: string | null;                            // Error message if any
  history: Array<{query: string, response: QueryResponse}>; // Query/response history
}
```

## API Response Mapping

The frontend will map the backend API response directly to the QueryResponse interface since they use the same structure. The mapping is 1:1 between the backend API response and the frontend data model.

## Validation Rules

- Query string must be non-empty and not exceed 2000 characters (validated by backend)
- Response status must be one of 'success', 'error', or 'empty'
- Matched chunks should have positive similarity scores
- Sources should be valid URLs or document identifiers
